# Workspace appearance — 2 November 2026

A moon/sun button sits beside Stars, Chat and Notifications in the existing header row. It switches instantly between light and dark mode without navigating, remounting the workspace, submitting forms or using AI. The choice is saved in this browser, follows the operating-system preference until the first explicit choice, and updates other open tabs. Storage restrictions fall back to the current session. A small head bootstrap applies the saved appearance before React paints. The bootstrap is included in the offline cache.

Dark mode uses a #0b1624 canvas, #142438 panels, #1b3048 raised surfaces, light neutral text, lighter blue links and the existing saturated blue action buttons. Error/success/warning surfaces use separate accessible tones. Vimbre's navy sidebar and blue brand remain. Public marketing and authentication retain their own light presentation. Exported task PDF documents are rendered separately and do not inherit the workspace theme.

References reviewed: [Atlassian color themes](https://atlassian.design/foundations/color/) and [blue palette adaptation](https://atlassian.design/foundations/color/color-palette), [Microsoft Fluent color](https://fluent2.microsoft.design/color) and [elevation](https://fluent2.microsoft.design/elevation/). Their guidance supports semantic colors, separate dark neutrals and deliberate accent contrast rather than image or page inversion.

The semantic dark overrides are generated from 22 workspace stylesheets by scripts/build-workspace-theme.mjs during each production build. They change color declarations only, preserve the source media queries and specificity, and leave light-mode source styles and images intact. Manual foundation rules handle browser-native controls, progress tracks, the workspace's inherited ink token, modal backdrops and the header. PostCSS 8.5.30 is pinned directly and in the lockfile for reproducibility.

Validation: 354 tests pass, including storage fallback, system and saved preference, subscriptions, early application and public-page exclusion. Contrast checks verify normal text, muted text, headings, links and semantic feedback at WCAG AA text contrast against the declared dark surfaces. Browser checks use actual components with sample data at 360, 768 and 1440 configured widths. My Day, Capture, Stars, the Handover document and Notifications were inspected. The four header icons share one row with 44px mobile targets and no horizontal workspace overflow at the checked phone width. Dark mode persisted after reload and route changes; switching back to light preserved an unsaved Capture source and its save state. A rendered Handover text scan reported no leaf text below 4.45:1. A missed inherited Stars text color and native white progress track were corrected. These checks simulate viewport sizes, not physical devices or every possible customer record.

No backend, permission, billing, analytics consent, AI operation or task workflow change is included.
