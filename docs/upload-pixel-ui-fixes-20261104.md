# Upload, tracking and daily panel fixes

The 4 November customer screenshots showed profile photo uploads failing and chat attachments not sending. Hosted Storage logs identified SQLSTATE 42501: `permission denied for function require_hr_admin`. Company-logo INSERT and DELETE policies referenced this intentionally revoked helper in an uncorrelated subquery. PostgreSQL could evaluate it for unrelated buckets.

Migration `20261104200816_isolate_company_logo_storage_permissions` replaces those two expressions with a current-company path check and an active HR-admin profile check. It does not grant access to the internal helper or change bucket visibility, upload limits, image compression, conversation membership or avatar ownership. The migration is installed on the Vimbre project.

Hosted rollback-only checks using authenticated roles verified a photo INSERT and read, a chat reservation and attachment INSERT/read, an employee's own avatar upload, rejection of employee company-logo writes and another member's avatar writes, and an administrator's company-logo upload. No test objects or reservations were committed. The broader fixture suite that creates fictional auth accounts could not complete the connector confirmation; focused checks avoided account creation. A physical-device customer upload through the Storage HTTP API remains a smoke check, distinct from the database permission checks.

The new regression suite performs actual storage-object INSERT operations as `authenticated`; earlier tests inserted objects as the database owner and therefore missed this policy failure. Chat now distinguishes attachment upload failure from an unconfirmed message send, preserving selected files and retry IDs. Profile upload errors no longer assume a connection problem.

Meta Pixel `1147746907945876` has a head loader. The supplied SDK initialization and PageView run only after a separate advertising consent choice, on public marketing pages. Existing analytics acceptance does not imply advertising consent. No unconditional noscript request is included because it would bypass that choice. Account, workspace and auth callback pages are excluded; automatic Meta events are disabled. PageView is the only Meta event added. Existing Google tracking and successful-account signup events retain their behavior. Cookie settings allow analytics and advertising separately and support withdrawal.

The role AI footer's second Close button is removed. The existing dialog header close remains. Priorities and day review use a bordered, labelled Hide/Show control beside the heading, with a 44px target and expanded-state linkage. Review actions occupy a separate row.

The closing landing animation has no playback button or looping motion. A short entrance sequence settles within two seconds and respects reduced motion. Skeleton bars are replaced with a labelled fictional supplier conversation, task/decision drafts and handover context. Existing heading, description and signup action are preserved.

Verification: 397 unit tests passed, including four Meta consent/route/withdrawal tests; application TypeScript and production/prerender builds passed. Lint has no errors and retains existing warnings. Actual components were checked at 320, 390, 768, 1024, 1440 and 1920 CSS pixels: no horizontal overflow in My day, the AI role dialog and the landing section; one AI-dialog close before/after saving; daily Hide/Show works; no landing play/pause control; no application console errors. A low-contrast inherited paragraph color was found in the browser and corrected. No files were deleted.
