# Board completion, role profile and AI service correction

The owner requested one Board Done column containing today's completions, investigation of AI planning failure with an available allowance, and a more readable profile-style role header. The owner explicitly chose to fill their own role content; no customer role record or title was populated by this release.

- Board Done now uses the server's `done_today` projection, calculated in the user's timezone. The extra Done today section remains only in List/Week. Board remains visible when no open tasks remain. The existing five-second completion/Undo transition stays in its original column until it settles. Dates are not changed.
- My role places the holder's initials/name and full-width title above an optional introduction, then department, manager and cover facts. The title retains its existing edit control and permissions; no authorization role is renamed. Introduction uses an explicit Save/Cancel form, retains failed-save drafts, and is editable only by the current holder. Existing role access controls govern reading; anonymous and cross-company access are denied. The field rejects access secrets using the existing role text guard. Introduction is profile text, not a private note or an automatically generated AI summary.
- The AI failure was reproduced as `service_role`: `private.billing_effective_plan(uuid)` lacked EXECUTE for the AI service. Earlier allowance/owner-level tests missed this distinction. Grant only the service role access to this private resolver; keep browser/anonymous access denied. The actual service-role reservation now succeeds, and the diagnostic transaction is rolled back. No provider call or paid tokens are used to test this change. The underlying provider still needs the user's normal retry to verify generation end to end.

Validation: 223 unit tests passed; production build/prerender/offline generation passed; lint has no errors (existing warnings remain). Focused browser checks cover one Done column with today's completions, exclusion of older completions, completed-only Board, intro save/failure/retry and mobile geometry at 320, 390, 768, 980 and 1440. A 390px profile screenshot was visually inspected. Database rollback fixtures verify owner save under the authenticated role, nonholder write denial, outsider read denial, anonymous denial and actual service-role AI reservation. Both backend migrations are installed before the frontend release. No real account content, customer messages or model charges were created by tests.
