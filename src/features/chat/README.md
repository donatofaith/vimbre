# Team chat

`/app/chat` is available to every active company member. Create a direct conversation or a named group with selected active teammates (maximum 50 participants including the creator). Group participants are fixed at creation in this first release. Participants can send plain-text messages, reply to individual messages, mention current participants and attach a supported internal record URL. Record links open existing guarded pages and never change access permissions. Files, typing indicators, delivery/read receipts, message edits/deletion, group membership administration and email/push notifications are outside this release.

ChatProvider loads the user's unread inbox and subscribes to recipient-scoped `chat_notifications` INSERT events through Supabase Realtime. It rechecks on focus/visibility and every 20 seconds while visible to recover from connection interruption. Notification events contain IDs and mention status; the authenticated RPC fetches displayed text. The header Chat shortcut and notification bell work throughout the workspace. Chat is not a sidebar item. The Chat shortcut carries an unread badge; notification items show only sender/mention context, conversation name and time, never message bodies or a duplicate Open chat link. Notifications link to the message's history window; opening old history does not clear newer messages. Read progress advances only to messages loaded at the bottom of a focused, visible conversation, including an anchored history window. No global read receipts are exposed.

The conversation list is paginated in pages of 50; its search filters the current page. Message history uses a 50-message sequence cursor; notification/reply links can anchor earlier history. A new-chat name search is server-paginated. Text is rendered with React escaping, never HTML. Mentions are explicit participant chips rather than inferred from arbitrary display names. All messages are limited to 4,000 characters. Failed sends preserve composer text and reuse a UUID for identical retries. Database RPCs serialize conversation writes, validate reply/mention membership and generate recipient notifications atomically.

All four public tables have RLS, authenticated SELECT only and no direct client writes. Active participants alone can read conversation rows and messages, regardless of HR/manager role; no employee role-record/draft RLS is expanded. Roster RPC returns only IDs, names and roles of active same-company teammates. Narrow public SECURITY INVOKER wrappers call private checked helpers with empty search paths and explicit authenticated EXECUTE grants. Realtime publishes only the notification table. Creation is limited to 10 new chats/minute per creator; sending to 60 messages/minute per sender.

Run `npm run check`, `node scripts/check-chat-browser.cjs` in the browser-test runner, and the rollback-only `supabase/tests/team_chat.sql` via an administrative SQL session. Tests create temporary example.invalid accounts inside a rolled-back transaction and never call email delivery. Fixtures verify direct reuse, reply context, mention/inbox counts, idempotency, tenant isolation, inactive access, anonymous denial and blocked direct writes. Browser fixtures verify group/direct chat, replies, mentions, links, retry, safe text, notification navigation, access failure and six widths. A real two-account Realtime delivery check is still needed after deployment; mocked browser requests do not verify websocket delivery.
