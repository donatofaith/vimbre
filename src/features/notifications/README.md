# Workspace notifications

The header bell combines chat alerts and personal deadline reminders. Chat's own shortcut continues to count only unread messages. Chat notification items never show message bodies.

Deadline reminders cover open/in-progress tasks, dated responsibilities and recurring deadline records. Due soon means the next three calendar days; today and overdue are separate stages. Date classification uses the browser's current IANA timezone on every inbox request. Reminders are computed from active source rows, not copied into stale event records. Completed/archived tasks and archived role items stop appearing. A new due date or transition to a new stage creates a new unread identity. No textual recurrence rule is parsed or automatically rescheduled; users update the next deadline after each occurrence.

The bell shows unread totals across all pages, with 50 reminders per page. Clicking a reminder opens its exact own task/role record and persists the read receipt. Mark as read is also available without navigation. Read reminders stay in the deadlines list while their source still qualifies. Notifications refresh on focus, visible-tab intervals (20 seconds), and work saves/archive changes. This is an in-app feature: no scheduler, email or OS push delivery is implied when Vimbre is closed.

Checked private functions enforce an active caller and query only that caller's current company and owner ID. Manager/HR roles do not add other people's reminders. Receipt writes go through an RPC that validates an actual current reminder key. Receipt table reads have owner-only RLS; direct writes and anonymous access are denied. Every source deep link still goes through existing page/RLS guards.

Validation: npm run check; scripts/check-chat-browser.cjs includes reminders, mark-as-read, exact-source navigation and optional responsibility date input. supabase/tests/work_notifications.sql is rollback-only and covers boundaries, timezone classification, exclusions, read persistence/idempotency, rescheduling, owner/tenant isolation and inactive/anonymous access. No email is sent. A redundant actions_owner_due_pending_idx currently duplicates the existing actions_due_idx; optional cleanup was not applied because the migration connector returned Invalid or expired requestState twice. It does not change permissions or reminder behavior.
